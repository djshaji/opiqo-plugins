# Android NDK Build Guide for GxPlugins.lv2

This guide explains how to build the GxPlugins.lv2 audio effect plugins for Android using the Android NDK build system.

## Overview

The GxPlugins collection includes 43 LV2 audio plugins optimized for guitar and audio processing. These Android builds provide nogui (headless) versions suitable for embedded audio applications, headless audio servers, or integration into Android audio applications.

### What's Included

- **43 plugins** with nogui builds (DSP processing only, no GUI dependencies)
- **Multi-architecture support**: ARMv7-a, ARM64-v8a, x86, and x86_64
- **Target Android API level**: 34
- **Build system**: Android NDK (ndk-build)
- **Special handling for plugins** with zita-resampler upsampling (14 plugins)

### Key Features

- Pure C/C++ code compatible with NDK
- No external dependencies beyond libc/libm
- Optimized for real-time audio processing
- Automatic architecture detection and optimization
- Consistent build across all ABIs

## Prerequisites

### Required Software

1. **Android NDK** (r26 or later recommended)
   - Download from: https://developer.android.com/ndk/downloads
   - Current recommendation: Android NDK r26b or later

2. **Bash shell** (for build scripts)
   
3. **Standard Unix tools**: bash, find, sed, grep

### Setup Android NDK

1. Extract the Android NDK to a directory (e.g., `~/Android/ndk/`)

2. Add NDK to PATH (add to `~/.bashrc` or `~/.zshrc`):
   ```bash
   export PATH=$PATH:~/Android/ndk/r26b/build
   ```

3. Verify installation:
   ```bash
   ndk-build --version
   ```

## Building

### Quick Start - Build All Plugins

```bash
cd /path/to/GxPlugins.lv2
./build_android_all.sh
```

This will:
1. Validate NDK installation
2. Compile all 43 plugins for 4 architectures
3. Generate `.so` (shared library) files in each plugin's `libs/[abi]/` directory
4. Log results to `android_build.log`
5. Display summary with success/failure counts

**Build time**: Approximately 5-10 minutes depending on system performance

### Build Single Plugin

To build a specific plugin:

```bash
cd GxAxisFace.lv2
ndk-build -j4
```

Output files will be in `libs/[abi]/libgx_AxisFace.so`

### Available Build Targets

Inside any plugin directory:

```bash
ndk-build           # Build for all architectures
ndk-build APP_ABI=arm64-v8a  # Build ARM64 only
ndk-build APP_ABI=armeabi-v7a  # Build ARMv7 only
ndk-build clean     # Remove build artifacts
```

### Clean Build

Clean all build artifacts across all plugins:

```bash
./build_android_all.sh clean
```

Or clean a specific plugin:

```bash
cd GxAxisFace.lv2
ndk-build clean
rm -rf libs obj
```

## Integration with Android Project

### Option 1: Copy to jniLibs (Recommended)

Use the provided script to copy all built plugins into the `jniLibs` structure expected by Android projects:

```bash
./copy_to_jniLibs.sh
```

This creates:
```
jniLibs/
├── armeabi-v7a/
│   ├── libgx_AxisFace.so
│   ├── libgx_blueamp.so
│   └── ... (all plugins)
├── arm64-v8a/
│   ├── libgx_AxisFace.so
│   └── ... (all plugins)
├── x86/
└── x86_64/
```

Copy the `jniLibs` directory to your Android project:

```bash
cp -r jniLibs /path/to/your/AndroidProject/app/src/main/
```

### Option 2: Manual Integration

Manually copy individual `.so` files to your Android project's `app/src/main/jniLibs/[abi]/` directories.

## Architecture Details

### Supported ABIs

| ABI | Architecture | Notes |
|-----|------|-------|
| **armeabi-v7a** | 32-bit ARM | Most compatible, good for older devices |
| **arm64-v8a** | 64-bit ARM | Required for Google Play, best performance |
| **x86** | 32-bit Intel | Emulator support, some tablets |
| **x86_64** | 64-bit Intel | Modern Intel tablets |

### Optimization Flags

Each ABI receives appropriate optimization flags:

- **ARM**: NEON instructions, optimized FPU
- **x86**: SSE/SSE2 when appropriate
- **All**: `-ffast-math -funroll-loops -fomit-frame-pointer` for DSP performance

### Special Plugins

14 plugins include **zita-resampler-1.1.0** for high-quality sample rate conversion:
- GxBoobTube, GxClubDrive, GxCreamMachine, GxEternity
- GxFz1b, GxShakaTube, GxSuperFuzz, GxSuppaToneBender
- GxSVT, GxTubeDistortion, GxValveCaster, GxVBassPreAmp
- GxVmk2

These are automatically built with additional include paths and compile flags.

## Troubleshooting

### "ndk-build not found"

**Error:**
```
ERROR: ndk-build not found in PATH
```

**Solution:**
1. Verify NDK installation: `ls ~/Android/ndk/r26b/build/ndk-build`
2. Add to PATH: `export PATH=$PATH:~/Android/ndk/r26b/build`
3. Test: `ndk-build --version`

### Build fails with C++ standard errors

**Error:**
```
error: variable has incomplete type 'struct ...'
```

**Solution:**
This usually indicates missing headers. Verify:
1. `lv2-headers/` directory exists at workspace root
2. Files `lv2-headers/lv2.h` and `lv2-headers/lv2/` are present
3. Delete `obj/` directory and rebuild: `ndk-build clean && ndk-build`

### Build fails for specific plugins

**Check the build log:**
```bash
tail -100 android_build.log
```

Common causes:
- Missing `plugin/gx_*.cpp` file (check file naming)
- Zita-resampler includes for 14 special plugins (already configured)
- SDK incompatibility (ensure NDK r26+)

**Rebuild single plugin with verbose output:**
```bash
cd GxAxisFace.lv2
ndk-build V=1 -j1
```

### .so files are too large

If `.so` files exceed expected sizes:
1. Strip symbols: `$(CROSS)strip -s -x -X libgx_*.so`
2. Verify release build: Check `APP_OPTIM := release` in `Application.mk`
3. Remove debug symbols: `ndk-build APP_OPTIM=release`

## Build Configuration

### Android.mk

Each plugin has `Android.mk` specifying:
- Source files and include paths
- Compile flags (C++11, optimization, visibility)
- Linker flags (section garbage collection, stripping)
- Dependencies (math library, log library)

### Application.mk

Global build configuration:
- **APP_PLATFORM**: android-34 (target API level)
- **APP_ABI**: all 4 architectures
- **APP_STL**: c++_shared (shared C++ standard library)
- **APP_OPTIM**: release (optimize for size and speed)

## Performance Considerations

### Real-time Safe Code

All plugins use real-time safe coding patterns:
- Pre-allocated buffers (no dynamic allocation in audio path)
- Lock-free parameter modulation
- No system calls in DSP processing

### Processing Load

Estimated CPU usage (typical values, device-dependent):
- **Simple plugins**: 2-5% per active instance (GxAxisFace, GxMicroAmp)
- **Medium plugins**: 5-15% per active instance (GxBlueAmp, GxClubDrive)
- **Complex plugins**: 15-25% per active instance (GxSVT, GxSupersonic)

These estimates are for 48kHz buffer sizes on modern ARM devices.

## Verification

```bash
# Count .so files for each ABI
find . -path "*/libs/armeabi-v7a/*.so" | wc -l
find . -path "*/libs/arm64-v8a/*.so" | wc -l
find . -path "*/libs/x86/*.so" | wc -l

# View specific plugin .so
ls -lh GxAxisFace.lv2/libs/arm64-v8a/libgx_AxisFace.so
```

## Advanced Topics

### Custom Build Configuration

Edit `GxAxisFace.lv2/Application.mk` to customize:

```makefile
# Build only ARM64
APP_ABI := arm64-v8a

# Use different STL
APP_STL := c++_static

# Different optimization
APP_OPTIM := debug

# Custom C++ features
APP_CPPFLAGS := -frtti -fexceptions -fno-rtti
```

Then rebuild:
```bash
cd GxAxisFace.lv2
ndk-build
```

### Compile Flags Reference

Common flags in Android.mk:

| Flag | Purpose |
|------|---------|
| `-D_FORTIFY_SOURCE=2` | Security hardening |
| `-O3` | Aggressive optimization |
| `-ffast-math` | Fast math operations |
| `-funroll-loops` | Loop unrolling optimization |
| `-fvisibility=hidden` | Symbol visibility control |
| `-std=c++11` | C++11 standard |
| `-Wl,--gc-sections` | Remove unused sections |
| `-Wl,--strip-all` | Strip all symbols |

### Using Different NDK Versions

The build should work with NDK r21 and newer, but r26+ is recommended.

To use a specific NDK version:

```bash
export ANDROID_NDK_HOME=/path/to/ndk/r26b
./build_android_all.sh
```

## Known Limitations

1. **No GUI builds for Android** - Only nogui versions are built (no Cairo/X11 dependencies)
2. **No automatic symbol export** - `.so` files should be loaded directly by host application
3. **LV2 bundles not created** - Only `.so` files are generated (bundle .ttl files not needed for Android)
